## Soft and client-only rules

- **Potwierdzenie revertu w UI** (`StatusControl.tsx:21-28`) — client-only, ale serwer wymusza to samo (`confirm` = `"true"`); bezpośrednie wywołanie API z `confirm=true` omija dialog — to zamierzone.
- **Ukrywanie niedozwolonych celów statusu** (`StatusControl.tsx:18`) — client-only kopia reguły z serwera (`applications.ts:112`).
- **Sprawdzenie pliku przed wysłaniem** (`CvPanel.tsx:71`, `CvLibrary.tsx:123`) — kopia `checkCvFile`, serwer i kubełek sprawdzają ponownie.
- **Ukrycie Edytuj/Usuń dla usuniętej notatki** (`NotesPanel.tsx:229`) — serwer i `edit_note` sprawdzają ponownie.
- Nie znalazłem reguły **wyłącznie** po stronie klienta (zakres: komponenty `src/components/applications/*`).

## Writers that work against a guard

W kodzie (`src/`) nie znalazłem pisarza, który je wykorzystuje (grep `.from("applications").update`, `.from("notes").update` → tylko `removeNote`, `notes.ts:73`).

## Failure handling

- **named error** — dominujący wzorzec: wyniki `{ ok: false, code, message }` w serwisach (`applications.ts:94-96,148-149`, `notes.ts:6-8`, `cv.ts:9-10`), mapowane na 400/404/409 w trasach.
- **generic error** — błędy Supabase opakowane `toServiceError` (`src/lib/services/errors.ts:11-23`), potem `failureResponse` → 503 `database_paused` albo zalogowane 500 (`src/lib/http.ts:152-158`).
- **silently corrects** (findings):
  - uzasadnienie zmiany stawki przycinane do 2000 znaków (`src/pages/api/applications/[id]/index.ts:23`);
  - nazwa pliku CV przycinana do 200 znaków (`src/lib/services/cv.ts:38`);
  - nieznane wartości `?status=` ignorowane (`search.ts:80-85`);
  - błąd Storage zawierający `exists|duplicate` traktowany jako sukces (ponowne użycie bajtów) (`cv.ts:28-32`);
  - niebezpieczny `next` → `/dashboard` (`redirect.ts:7-11`).
- **logs and continues** (findings):
  - cron keepalive bez `SUPABASE_URL`/`SUPABASE_KEY`: `console.error` i `return` bez rzucenia — przebieg crona nie pokaże się jako nieudany (`src/worker.ts:21-25`); przy błędzie pingu rzuca dalej (`:33-38`);
  - `/api/health` loguje przez `console.error` zamiast `logError` i odpowiada 503 (`src/pages/api/health.ts:20-26`);
  - `/api/alerts/issue` celowo nigdy 5xx, tylko `console.warn` (`src/pages/api/alerts/issue.ts:10-17,66-69`).
- **swallowed silently** — nie znalazłem (zakres: `src/lib/services`, `src/pages/api`, `src/worker.ts`).
